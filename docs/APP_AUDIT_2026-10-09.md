## 1. Summary

The shell around the map is in good shape: skip link, visible focus on every tab stop, a correct combobox/listbox for search, a working light/dark theme with no dark-mode contrast failures, a purchase dialog that traps focus and closes on Escape, no horizontal overflow at 375, 820 or 1440 px, and an axe scan of `/map` that returns a single issue. The privacy, terms, help, contact and notifications pages that were missing on 10-02 now exist and are clean.

The problems are in four places:

- **The server could be crashed by one request.** `GET /api/v1/enrichment/bulletin` segfaulted the API worker every time (psycopg2-binary's bundled TLS next to a numba JIT compile on another thread). The dev reload supervisor did not respawn the dead worker, so the port kept accepting connections that nothing answered. That is the "map tiles take forever" report. **Fixed in the working tree during this audit** (§9); `stats_service.py` still has the same exposure.
- **The new parcel side sheet has serious responsive and robustness gaps.** On a phone the map action buttons sit on top of the sheet and cover its close button; on a tablet the sheet covers the very parcel it describes. Three of its endpoints take 20–40 s cold, the PDF link navigates away from the map to a request that takes 7–42 s or returns a bare 500, and signed-out "Save" spins for 10 s.
- **Some of what the panel says is misleading or inconsistent.** An "indicative value" of €6.6–13.1 M is computed as parcel area × residential price per m². The solar block says Verona has no data while the solar map layer has it. Internal identifiers (`omi-area-range-v1`, "SISTER SQLite", `veneto__particelle`) are shown to end users.
- **Two map layers are wrong or slow because of data plumbing.** `flood-hazard` shows nothing anywhere in Italy because its geometry was reprojected from the wrong CRS (repair script ready, not yet applied); `market-zones` still takes about 5 s per tile until one more foreign-server option is set.

## 3. Findings

### Critical

#### C1. One unauthenticated request crashes the API worker (psycopg2 TLS vs numba)
- `GET /api/v1/enrichment/bulletin` returned an empty response (`curl` status 000) after 8–55 s on every call, and the worker PID changed each time.
- Reproduced on a throwaway instance with `-X faulthandler`: `Fatal Python error: Segmentation fault`, crashing thread in `psycopg2/__init__.py:122 connect` ← `bulletin_store._connect` ← `stats_service.get_criticality_bulletin` (via `asyncio.to_thread`), while another thread was inside `numba/.../codegen.py` / `llvmlite ... newpassmanagers.run` (the datashader warm-up).
- Narrowed to TLS: `PGSSLMODE=disable` stops the crash (3 × 200, 0 fatal errors); `PGGSSENCMODE=disable` alone does not. Standalone, `get_bulletin()` takes 0.5 s and returns 1.5 MB, so the data is fine.
- `map_layers.py:262` already documents the same class of crash ("psycopg2-binary bundles its own libpq and OpenSSL … its TLS connection setup segfaulted the API worker") and moved map reads to asyncpg. Four psycopg2 sites remained.
- **Second effect:** the dev reload supervisor (`uvicorn reload=True`) did not respawn a dead worker. It kept the listening socket with 86 connections queued, `/health` timed out, and the worker stayed a zombie for 7+ minutes. Touching a watched file restarted it.
- **Impact:** anyone (or the parcel sheet's "Criticality bulletin" section on every parcel click) can take the whole app down.
- **Status:** `land_registry/pg_ssl.py` adds `plain_loopback_dsn()` (TLS off for loopback only; remote and explicit `sslmode` untouched), applied in `bulletin_store.py` and `datashader_service.py`; 12 unit tests in `tests/test_pg_ssl.py`. Verified on a fresh instance with no environment workaround: 3 × 200, no fatal error. **Not yet applied** to `land_registry/stats_service.py` (psycopg2 `ThreadedConnectionPool`, ~line 1041), which has uncommitted edits from someone else; it has the same exposure. Longer term, move the remaining psycopg2 users to asyncpg or a source-built psycopg2.

#### C2. `flood-hazard` layer shows nothing anywhere in Italy
- All 28 tiles empty at Ravenna z10, zero features at five other locations, although `/api/v1/map/layers/health` says `available: true`, 85,460 rows.
- Cause: the ISPRA flood shapefiles are EPSG:3035 (ETRS89-LAEA); the importer treated them as EPSG:32632, so the stored geometry sits at lon 41–48, lat 11–20. This is a wrong-CRS import, not an axis swap (a flip would have written worse data). Verified against the shapefile header (true bbox lon 7.1–19.5, lat 36.8–46.3) and against `area_sqm`, which is exact because it was computed on the native coordinates.
- The inverse transform recovers the data exactly: `ST_Area(corrected::geography) / area_sqm = 1.0000` for every row of a 400-row sample, and the result spans Italy.
- A user looking at a missing hazard layer reads "no flood risk here". This is a false negative on a safety-relevant layer, with no indication in the UI.
- **Status:** importer fixed with per-hazard CRS, an in-Italy extent check and tests (`aecs4u-stats`, 12 tests pass). **Repair script written, not applied:** `aecs4u-stats/migration/repair_flood_hazard_crs.sql` (guarded, idempotent, rolls back if the result is outside Italy). Run it in the `hazards` database. The canonical database may hold the same wrong geometry in `spatial.hazard_area`; not checked.

### High

#### H1. Mobile: the map action buttons cover the parcel sheet and hide its close button
- At 390×844 the eight round buttons (basemap, purchases, locate, share, reset, table, Google Maps, Street View) stay on top of the sheet's top-right corner. They cover the **×** close button and half of the PDF button ([screenshot](app-audit-2026-10-09/parcel-panel-mobile-390.png)).
- The only visible way to dismiss is "Clear selection", which is off-screen to the right inside a horizontally scrolling footer.
- The tab strip ("Energ…") and the action footer ("Find adjacent parce…") both scroll sideways with visible scrollbars and no affordance.
- The sheet takes 67 % of the viewport (564 px of 844) and the red "Sign in to save parcels" toast sits half under it.
- **Fix:** hide or re-dock the action column while the sheet is open on narrow screens; make the sheet a bottom sheet with its own drag/close handle; wrap the footer actions or collapse them into a menu; let the tab strip wrap or scroll with edge fades.

#### H2. Tablet and narrow desktop: the sheet covers the selected parcel and the search card
- At 768 px the sheet is 480 px wide at x = 228–708, overlapping the right part of the search card ("Privac…" cut) and covering the highlighted parcel ([screenshot](app-audit-2026-10-09/parcel-panel-tablet-768.png)). At 1024 px it is docked to the right and the parcel stays visible only because the test parcel was near the centre.
- The decision for this panel is that the sheet keeps the selected parcel visible. Nothing re-centres the map when the sheet opens.
- **Fix:** on selection, `easeTo` with right padding equal to the sheet width (`map.setPadding` / `padding` option) when the parcel would fall under the sheet; below ~900 px switch to the bottom-sheet pattern from H1.

#### H3. The parcel sheet depends on endpoints that take 20–40 s, and skeletons never resolve
Timings for parcel `L781B016600.342`, signed out, 12 calls per selection (no duplicates in a clean run):

| Endpoint | Cold | Warm |
|---|---|---|
| `/parcel/hazards/{ref}` | 22.5 s, 33.4 s | 0.03–0.05 s |
| `/fires?lat&lng&radius_km=25` | 30.5 s | 0.005 s |
| `/parcel/report/{ref}` (PDF) | 7.4 s then **500**; 42.5 s on the next call | – |
| `/parcel/opendata` | 3.5–4.6 s (every parcel) | – |
| `/parcel/by-reference/{ref}` | 2.7 s | 0.4 s (404 case) |
| `/parcel/pvp` | 1.7 s | – |

- Result in the UI: Criticality bulletin, Active fires and Points of interest show grey skeleton bars for 10+ s (see [adjacent screenshot](app-audit-2026-10-09/parcel-panel-adjacent.png)); "Loading parcel details…" stays in the bottom-left toast for 4+ s.
- The bulletin endpoint also crashed the server (C1).
- **Fix:** set a per-section timeout (say 6 s) and render "Could not load. Retry" instead of an indefinite skeleton; cache and prefetch the slow ones; investigate why `hazards` and `fires` take 20–30 s the first time (probably the same psycopg2 connection setup that `stats_service.py:300` says can hang).

#### H4. "Download PDF" navigates away from the map and can end on a bare 500
- The control is `<a aria-label="Download PDF" href="/api/v1/enrichment/parcel/report/…">` with no `download` attribute and no `target`, so it replaces the map page (and loses the open sheet) while the server works for 7–42 s. One call returned `500` with the 21-byte body `Internal Server Error` as `text/plain`.
- No progress, no error handling, no way back except the browser Back button.
- **Fix:** fetch the PDF, show a progress/disabled state, trigger a download from a blob, and show an inline error on failure. Fix the 500 and the 42 s generation (it is dominated by the slow lookups in H3).

#### H5. Signed-out "Save parcel" spins for ~10 s before saying "Sign in to save parcels"
- Timeline measured in the browser: button shows "Saving…" immediately, then 10.2 s later "Save parcel" with the status "Sign in to save parcels". The API itself answers 401 in 20 ms, and `window.landRegistrySignedIn` is already `false` on the page.
- A global progress card ("Saving parcel… 5 s, 2 tasks in progress") appears over the shortlist button for the whole wait.
- **Fix:** when signed out, show the sign-in prompt immediately and never start the task.

#### H6. "Indicative value" is parcel area × residential price per m², shown as a headline number
- For a 2,624.6 m² parcel next to the Verona Arena the sheet shows **Indicative value 6.562.500 € – 13.125.000 €**, **Gross rental yield 11,52 %**, **Price to mean taxable income 370,4 years**, and a header KPI "Sale price (OMI) 2500–5000 €/m²".
- The estimate multiplies the *plot area* by the OMI €/m² band for "Residential apartments" (the "Surface used for the estimate" field is pre-filled with the parcel area). A plot area is not a floor area, and 15 OMI zones are listed as a flat run of text with no selector.
- A disclaimer exists, but it sits below the numbers in small text. These figures will be read as a valuation.
- Model identifiers are printed next to the values: `omi-gross-rental-yield-v1`, `omi-zone-percentile-midrank-v1`, `omi-area-range-v1`, `omi-mef-price-income-v1`.
- **Fix:** do not show a value range until the user supplies a floor area or a building is matched; make the OMI zone/type a control (select), not a list; put the caveat in the same visual block; move model IDs to a "Methodology" disclosure.

#### H7. The sheet and the map layer disagree about solar potential
- Sheet (Energy tab): "Municipal solar potential is not available for this municipality." API: `blocks.solar` = `available:false`, source `aecs4u-stats serving.municipality_profile`.
- Map layer `solar-potential` reads `solar.solar_potential_comuni`, which has Verona (023091: 58,471 buildings, 82.1 % high viability).
- This is the same two-source problem the panel redesign should remove; the user-visible effect is that the product contradicts itself.
- **Fix:** point the panel's solar block at the same relation (via the municipality lookup) or retire one of the two.

#### H8. Panels cover the map attribution
- With the Layers panel open on desktop the attribution box (x 1046–1430, y 866) overlaps the panel (x 1083–1375, bottom 882); only "© Esri…" and "…pLibre" remain visible. The parcel sheet also covers it (only "Libre" is visible, [screenshot](app-audit-2026-10-09/parcel-panel-desktop.png)). On mobile the Layers panel does the same.
- Esri, OpenStreetMap and MapLibre attribution requirements assume it stays visible.
- **Fix:** keep the attribution control above the panels (raise its z-index and reserve space), or move the panels' bottom edge above it.

### Medium

#### M1. Layout shift and long tasks at load
- CLS **0.18** (desktop light), **0.18** (dark), **0.10** (mobile); the threshold for "good" is 0.1. Source: `main#main-content` animates from 1160 px to 1440 px wide over ~300 ms (theme sidebar collapsing) between 2.1 and 2.4 s, shifting the whole map; the MapLibre control column also moves from x 1334 to x 1036 once.
- Long tasks of 297 ms and 129 ms on first desktop load (64 / 51 ms warm).
- **Fix:** render the shell collapsed on first paint for `/map` (class on `<html>` before first paint), or reserve the final width; call `map.resize()` once after the transition.

#### M2. The theme ignores the OS colour scheme on first visit
- With `prefers-color-scheme: dark` emulated, the page loads light (`localStorage.theme` defaults to `light`). The toggle works, persists across reload, switches the basemap radio to Dark, and has no dark-mode contrast violations.
- The toggle has no `aria-pressed`, and its label ("Toggle between light and dark theme") does not say the current state.
- **Fix:** default to the OS preference when nothing is stored; expose state with `aria-pressed` or a state-bearing label.

#### M3. Keyboard and focus management gaps
- **Escape** does not close the Layers panel, the attribute table or the parcel sheet. It does close the basemap popover, the search results and the purchase dialog.
- Opening the Layers panel or the sheet does not move focus into it (focus stays on the toggle / the map canvas). Closing either drops focus to `<body>`.
- Tab order puts the map canvas and the MapLibre controls (bottom right) **before** the right-hand action stack and the Layers/Shortlist buttons, the reverse of visual order *(open since 10-02 L5)*.
- Parcels can be selected only by clicking; there is no keyboard way to pick a parcel from the map (search by reference is the workaround).
- Icon-only buttons are 32×32 (copy link) and 24×24 (close), under the 44 px touch guideline; the minimum 24 px in WCAG 2.2 is met.
- **Fix:** Escape handlers and focus-return on every panel; `aria-expanded` is already set; consider a keyboard parcel picker (e.g. Enter on the map selects the parcel under the crosshair).

#### M4. Parcel sheet tabs are buttons with the wrong semantics, and the scroll-spy misbehaves
- The six tabs (Value, Property, Territory, Context, Energy, Data) are plain `<button>`s inside no `role="tablist"`, with `aria-current` toggled by scroll position. Arrow keys do nothing; each tab is a separate tab stop.
- Clicking **Energy** or **Data** highlighted **Property** / **Context** instead, because the section sits at the end of the scroll range. In one run the header, KPI strip and tab bar scrolled out of view and the action footer floated mid-sheet above empty space ([Energy](app-audit-2026-10-09/parcel-panel-energy.png), [Data](app-audit-2026-10-09/parcel-panel-data.png)). I could not reproduce that layout on demand a second time (the bottom-of-scroll state was correct in later runs), so it is intermittent.
- Every tab click rewrites `location.hash` (`#valore`, `#immobile`, `#territorio`, `#contesto`), and the copied link carries it.
- After the sheet is closed the URL still contains `parcel=…&parcel_id=…` and a hash, so a reload re-opens the parcel.
- **Fix:** either implement real tabs (roving tabindex, arrow keys, `role="tab"/"tabpanel"`) or a heading-anchored table of contents; use `IntersectionObserver` with a bottom-of-scroll rule; do not write the hash; clear `parcel` from the URL on close.

#### M5. The sheet is long, repetitive and mostly empty for most parcels
- 22 collapsible sections (`<details>`), all open by default; the content area is ~3,500 px tall inside a 446 px window.
- 13 of them (Municipality, Income (IRPEF), Census 2021, Safety, Demographic indicators, Quality of life, Points of interest, Parcel-scale hazards, EGMS, Criticality bulletin, Active fires, Agenzia Demanio, Municipal solar) were bare headings or grey skeletons at the 3.7 s mark. Several later resolve to a single line such as "… is not available on this server", others stay as skeletons (H3). Either way the reader scrolls past 13 headings to learn that nothing is there.
- "Data coverage 2/20" lists 18 blocks as "Not available": the sheet advertises a lot it cannot deliver. KPI strip: "SISTER records —" for every signed-out user, with no explanation.
- The **Value** tab opens with the cadastral identity block, and OMI quotes appear under it.
- **Fix:** hide sections with no data (or collapse them into the coverage list); collapse long sections by default; explain "—" ("sign in to see SISTER records").

#### M6. Internal terms and infrastructure details are shown to users *(open since 10-02 M5)*
- Layers panel (every row, 14 times): "Available · From zoom 5 · Source version shown in feature details · aecs4u-stats PostgreSQL/PostGIS". Also "cadastral PostgreSQL/PostGIS", "Needs configuration".
- Sheet: "Source: veneto__particelle", "Source: SISTER SQLite", "Source: PVP PostgreSQL", "OpenData PostgreSQL", "aecs4u-stats (PostGIS asyncpg)", "Not available on this server", "ISPRA hazard polygons are not available on this server", "This data source is not available on this server".
- **Fix:** user-facing source names and dates; keep infrastructure names in a developer diagnostics view.

#### M7. Number and date formatting is inconsistent
- In the English UI: "2624,6 m²" (Italian decimal comma, no thousands separator) next to "6.562.500 €" (Italian thousands dot) and "11,52 %" (space before %, comma). In the Italian UI the area is still "2624,6 m²" (should be "2.624,6 m²").
- **Fix:** one formatter per locale (`Intl.NumberFormat`) used by every block.

#### M8. Attribute table: accessibility and presentation
- Headers are raw column names (`canonical_referenc…`, `national_cadastral…`, `municipality_id`); no `scope` on `<th>`, no caption, no sort controls; 100 rows per page, all columns visible.
- It opens as a 351 px strip across the bottom of the map (z-index 4) over the shortlist and attribution; Escape does not close it.

#### M9. Content-Security-Policy blocks the theme's preloads and is permissive
- Console errors: *"Connecting to 'https://fonts.googleapis.com/css2?family=Inter…' violates … connect-src"* on `/auth/register` and on `/map` whenever a parcel is selected; seven *"Connecting to 'https://unpkg.com/leaflet… .css'"* errors on `/map-legacy`. The stylesheets still load via `<link>`, but the preload requests fail (`Couldn't load preload assets: ProgressEvent`), so the fonts/CSS preload optimisation does not work and the console is noisy. Add `fonts.googleapis.com` and `unpkg.com` to `connect-src`, or stop preloading via `fetch`.
- `script-src` allows `'unsafe-inline'` and `'unsafe-eval'` plus six third-party hosts; `style-src` allows `'unsafe-inline'`. Not exploitable on its own but it removes most of the CSP's value *(open since 10-02 M12)*.

#### M11. No SEO or app metadata *(open since 10-02 L1)*
No `<meta name="description">`, canonical or Open Graph tags on any page; `/map` has no `theme-color`; `/robots.txt`, `/sitemap.xml`, `/manifest.json` return 404. `/` is a 307 (temporary) to `/map`.

#### M12. Language switching is not persistent and resets the view
- The picker links to `?lang=it`, and no language cookie is set (`Set-Cookie` absent), so the next navigation to `/map` is English again. The link also drops `lat/lng/zoom` and any selected parcel; after switching, the map was in Cagliari.
- With `Accept-Language: it` the server-rendered UI is Italian and, of 101 strings collected from the sheet, only three raw labels stayed English by my heuristic; other leftovers: layer status words ("Available", "Needs configuration"), `title`/`aria-label` strings ("Toggle between light and dark theme", "Zoom in", "Sign in to use sales data"), raw labels `source release`, `municipality code`, `municipality name`, and the whole source line.
- **Fix:** set a long-lived `lang` cookie from the picker, preserve the query string, and translate the remaining strings.

#### M13. Critical rendering path of the map page
- The theme brings Bootstrap CSS + JS bundle and Font Awesome (3,249 CSS rules between them), design tokens, layout, components, MapLibre CSS, map-v2 CSS, purchases CSS and a Google Fonts stylesheet: **9 stylesheets, 8 scripts**, with `bootstrap.bundle.min.js` and `theme.js` not deferred. Total 53 resources on load, 35 of them tile/API fetches, 33 to `server.arcgisonline.com`.
- DOMContentLoaded 0.6–1.7 s, FCP/LCP 0.6–1.6 s on localhost; JS heap 8–9 MB; 614 DOM nodes. Fine on this machine, but all of it is cross-origin on a real network.
- **Fix:** defer the theme scripts, load Font Awesome as a subset or inline SVG, `preconnect` for the tile host and `unpkg.com`.

#### M14. Static assets are `Cache-Control: no-cache`
`/static/map-v2.js` (178 KB) returns `etag` and `cache-control: no-cache`; every page load revalidates. The HTML already uses `?v=` fingerprints, so these can be `public, max-age=31536000, immutable` in production. Verify on the deployed build; this may only be the dev setting.

#### M15. Public API documentation and cookies
- `/docs`, `/redoc` and `/openapi.json` are public, and `/docs` loads Swagger from a CDN (11 s here).
- A session cookie `aecs4u_session` (HttpOnly, SameSite=Lax, 4 h) is set on the first anonymous `GET /map`, with no `Secure` flag in dev. The consent banner was removed deliberately, and `/privacy` documents cookies; confirm that the wording covers a session cookie issued before any sign-in. #### M16. Map controls overlap the search privacy line and are cryptic

#### M17. Hover popup interferes with the selected parcel

## 4. What worked

- **Search:** `role="combobox"` with `aria-controls`, `aria-expanded`, `aria-activedescendant`; arrow keys move the active option; Escape closes the list; "No result" is announced through `aria-live`; typing "Vero" returned 20 municipalities (the list was populated within the 1.8 s I waited).
- **Keyboard:** all ~26 tab stops on `/map` have a visible focus indicator (outline or shadow); the skip link appears on focus and targets an existing `#main-content`; the basemap popover and purchase dialog close on Escape; the purchase dialog keeps focus inside and has an accessible name.
- **State in the URL:** `lat`, `lng`, `zoom`, `parcel` and `parcel_id` restore the view and the selection; "Copy link" writes the link to the clipboard and announces "Map link copied".
- **Theme:** toggle persists, basemap follows, and axe reports no colour-contrast failure in dark mode on `/map`.
- **Responsive:** no horizontal scroll on any audited page at 375/390, 820/768 and 1440; the sheet width (518 px at 1440, 480 px at 1024/768) matches the 480–560 px side-sheet decision on desktop.
- **Security headers:** HSTS, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Cross-Origin-Opener-Policy: same-origin`, a restrictive `Permissions-Policy` (geolocation=self only), request IDs.
- **Operations:** `/health` is liveness only, `/ready` returns 503 when the map source is unreachable (it can exceed its own 3 s limit on the first call after a restart, which returned 503 once); tile caching and request coalescing work (warm tiles 5–25 ms).
- **Previously reported and now fixed:** `/privacy`, `/terms`, `/help`, `/contact`, `/notifications` exist and are fast and axe-clean; `GET /auth/logout` shows a confirmation instead of signing out; the retry storm no longer reproduces; `/map-v2` redirects (308) to `/map`; the three `*_table` routes return 200 (not re-audited for content); Italian renders when the browser asks for it.
